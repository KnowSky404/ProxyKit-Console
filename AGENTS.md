# ProxyKit Console development

## Scope and boundaries

Console browses resources and generates subscription snippets. ProxyKit owns public resources and generators; ProxyKit-Private owns private sources/dist; Gateway authenticates and distributes. Never edit those repositories as a side effect of Console work. Preserve LICENSE.

- `src/app`: application composition, navigation and theme.
- `src/components`: small accessible shared UI controls.
- `src/features/{catalog,preview,subscriptions,gateways}`: feature UI and client configuration generation.
- `src/types`: shared Resource, ResourceDetail, ResourceProvider and protocol types.
- `src/providers`: browser adapters to same-origin Console APIs; no server credentials.
- `src/config`: reviewed public source configuration and generated catalog.
- `src/lib`: shared validation, filtering and bounded text handling.
- `worker/providers`: server-side adapters; `worker/index.ts`: HTTP routing and safe errors.
- `scripts`: reproducible maintenance; `tests`: unit, UI and browser checks; `docs`: contracts and operations.

Do not create empty layers or speculative infrastructure. Reuse the ResourceProvider interface. Add a new provider only with a real, documented contract, server-owned source configuration and tests. App owns selection/filter state; details own preview state. Cancel superseded requests. Keep remote content inert React text. Controls need labels, visible focus and accessible feedback.

## TypeScript and tools

Use strict TypeScript; no `any`, unchecked double assertions or suppression to silence defects. Validate unknown input at trust boundaries. Shared types belong in `src/types`; avoid copies. Use typed fixed error codes on the server; never echo upstream payloads, credentials or arbitrary exception messages. Preserve async error and cancellation handling.

Use Bun 1.4.4 and Node 24+; install with `bun install --frozen-lockfile`. Dependencies are exact-pinned, with `bun.lock` committed. TypeScript 6 is intentional until typescript-eslint supports TS 7. The pinned cf CLI/Vite integration is beta; do not update it independently of build/runtime validation. Use the cf CLI for this project, with `cloudflare.config.ts`. Do not introduce a Wrangler JSON/TOML config or another deployment system.

Run `bun run format` after edits. Before committing run `bun run check`, and `bun run test:e2e` for rendered behavior changes. New nontrivial logic needs a small meaningful regression test. Test catalog paths/schema, unsupported formats, URLs, snippets and policy injection, preview byte limits/UTF-8, failures, empty results and user interactions. Keep test fixtures in tests, clearly identified; never populate the real catalog with them. Browser tests use Playwright Chromium desktop/mobile. New bindings require regenerated platform types; don't hand-copy Env.

## Catalog

`src/config/catalog.json` is generated by `bun run catalog:sync`, using authenticated `gh` to inspect ONLY the fixed Public repository. Run `gh auth status --hostname github.com` first. Never sync Private. Preserve revision/size/source validation, reject truncated trees, symlinks and unsupported paths; never display placeholder files. Review catalog diffs and run `bun run catalog:validate`. See docs/catalog.md for the update process.

## Security

No private resources, tokens, PATs, secrets, device credentials or private build outputs in this public repository, logs, fixtures, browser storage or bundles. Never put secrets in `VITE_*`. Long-lived service credentials belong in Worker Secrets after a reviewed authentication design. Public V1 needs no secrets.

Preview accepts catalog IDs only, never arbitrary URLs/repositories/refs. Retain fixed source allowlists, redirect rejection, timeout, UTF-8 validation and 128 KiB streaming byte cap. Never execute scripts/plugins, inject HTML, compile SRS or open a CORS proxy. Source trust, Gateway auth and permission filtering stay on the server. Web user identity, device subscription identity and service identity are separate. DEVICE_AUTH holds digests; original device tokens cannot be recovered. Never claim a future Gateway endpoint already exists.

## Git, PRs and documentation

Inspect status before work and preserve unrelated changes. Use an independent task branch or worktree; never merge automatically. Make atomic Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`). Review the connected code and diff for security and correctness, then push the task branch and open a PR when authorized by the task. Wait for configured CI/review checks and fix failures. Never delete branches, deploy production, create Cloudflare resources or change domains without explicit authorization.

Prefer authenticated `gh` for GitHub operations; check `gh auth status` for the target host before the first authenticated operation. Use git for local changes and transport. For GitHub issue/PR prose use a temporary file written with a quoted heredoc, then `--body-file`; never inline multiline/Markdown text in shell arguments. Never print credentials.

Update README and relevant architecture/security/protocol/operations docs with behavior or contract changes. Distinguish implemented, proposed and unverified behavior. Record source syntax evidence and minimum client versions. Don't claim hardware validation from string tests. Keep deployment manual and credential-free in PR CI.
